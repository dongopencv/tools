# docs/log/ —— 每日状态记录

一天一个文件，命名 `YYYY-MM-DD.md`。**只写可核对的事实，不写感想。**

三节固定，不要多也不要少：

| 节 | 写什么 |
|---|---|
| 推进了什么 | 今天真实落地的改动：提交号、脚本、文档、票的状态变化。能被 `git log` 或 `gh issue view` 证伪的都算 |
| 卡在哪 | 具体的阻塞点：哪张票在等谁、哪个工具坏了、哪个前提没满足。**不写"感觉不顺"** |
| 明天第一件事 | 一句话，具体到能直接开始做。不是"继续跟进 X" |

为什么要有这个：

- 注意力有限，跨天就得靠文字接住，否则第二天要从零重新想起来。
- 「我以为上周做过了」这类错误，只有记录能戳破。
- 它和 `docs/research/` 的分工：research 记**结论与判断怎么变化**，log 记**今天到了哪一步**。

不要写：日报式的自我评价、没有对应的票的想法、任何凭据或口令。
