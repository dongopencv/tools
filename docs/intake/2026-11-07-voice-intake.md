## 一句话总纲

这个仓库不是工具堆，是 **PC1 的长期维护体系**，三重定位：

| 层 | 落点 | 管什么 |
|---|---|---|
| 工具层 | `tools/`、`AGENTS.md` | 这台机器上跑了什么、怎么用、踩过什么坑 |
| 认知层 | `docs/research/` | 对外部项目的长期判断、依据、**以及被推翻的判断** |
| 状态层 | `docs/log/` | 今天推进了什么、卡在哪、明天第一件事 |

语音里那九簇需求，全部是这三层的展开——没有第四层。**私人生活记录（日记 / 健身）不在这个仓库里**，理由见 §2。

## 1. 仓库定位：工具维护 + 个人认知维护

**原话**
> "我这个仓库是作为我就是我这边开发的一些工具，长期维护一些工具的就是使用。而且还有一个就是对我个人的一个维护，个人维护是多角度的，一个是认知这一块。"

**校正**
"对我个人的一个维护"容易被读成"私人生活管理"，但紧跟着的解释是"多角度的，一个是认知这一块"——**指的是认知维护，不是生活管理**。依据：同一段话里他接着说的全是知识领域（下载、代理、磁力链），没有一句涉及私人事务。

**实际需求**
仓库要同时承载"工具怎么用"和"我判断过什么"，两者的写法要求不同：工具写操作步骤，认知写结论 + 依据 + 失效条件。

**归属**
已落地：`AGENTS.md`「仓库的三重定位」一节 + `docs/research/` 写法要求。决策图 #47 的目的地。

**待确认** —— 无（已在 grilling 中确认）。

## 3. 认知层：下载与出网通道的广度

**原话**
> "我要知道就是说代理这个思路，我我现在大概能知道了。然后就是 IP 返代这些我也要去学习。然后呢还有就是呃包括磁力链这些我也要去学习一下。然后就是还有就是比如说用了镜像之后还可以再去加速这些。我之前看 agent 它是比如说本地加什么缓存之类的就是速度更快，就是那个延时做的更低这些我也要去学习。就是它这些知识它的特点是呃广度，一定是广度，就是我细节方面可以让 AI 去帮我干活，但是我的广度要有。"

**校正**
- "IP 返代" → **反向代理**（同音，且与"代理"并列出现，构成"正向代理 / 反向代理"这一对）。
- "本地加什么缓存" → 指 agent 工具在本地做**响应缓存 / 连接复用**来降低延迟，不是 CDN 缓存。
- 关键限定词是那句"**广度要有，细节可以让 AI 去帮我干活**"——这是验收标准，不是修饰。他要的不是六份教程，是**一张能选路的判断表**。

**实际需求**
六块知识各留一页结论：代理、反向代理、磁力链、镜像之后再加速、本地缓存降延迟、下载通道选型。每页必须是"给个新场景我能选对通道，并说清它什么时候失效"。

**归属**
票 #50「认知层：下载与出网通道的广度页」（research）。已有本机实测基础：`docs/network-baseline.md`（#4 落地）。

**待确认**
- [ ] 认知页的粒度：一页覆盖一块知识（六页），还是合成一张总表 + 六份附录？（推荐总表 + 附录：广度要的是能在 30 秒内选对通道）

## 4. 大模型 API 在 DSH 里接入

**原话**
> "就是要学习，就是大模型 API 的这一块，就是 API 的调用，就不是说是它的具体原理啊。这方面呃，这方面原理是一小部分，然后最关键的就是各个 AGENT 工具我怎么去拿到他们的 API……因为我不喜欢用其他的 AGENT，这 AGENT 用各种问题我一定要在 DSH 用，然后现在已经是有了 TREE CONNECT 这个的这个，然后还有 WORK BABY CONNECT 这个也用起来了，然后还有就是 XD 那个这几个我都要去研究去学习。"

**校正**
- "TREE CONNECT" → `dsh-connect-trae`（Trae 的连接插件，本机已装 4.6.12）。
- "WORK BABY CONNECT" → `dsh-connect-workbuddy`（WorkBuddy，已装 5.17.0）。
- "XD" → `dsh-xdpool`（已装 2.5.1）。
- "不是说是它的具体原理，原理是一小部分" → **要的是"怎么拿到额度、怎么配进 DSH"，不是模型原理**。这是范围裁边，很重要：按"学原理"去做会做成一篇论文，做错。
- "不喜欢用其他 AGENT" → 不是排斥它们的**服务**，是排斥它们的**客户端**。本机 Trae / WorkBuddy 本体都装着，他要的是借它们的 token 在 DSH 里跑。

**实际需求**
三家（Trae / WorkBuddy / XD）各自：凭证从哪来、怎么落到 DSH、能跑什么模型、什么情况下会断（额度 / 风控 / 版本升级）。产出是一张"接入矩阵"，不是三篇教程。

**归属**
票 #51。前置事实：三家插件都已装且都在 profile bundles 里。

**待确认**
- [ ] 这张矩阵要不要包含"额度耗尽时的降级顺序"？（推荐要：这决定了他日常能不能闭眼用）

## 5. 中转站自定义模型为什么用不了

**原话**
> "还有就是我买的中转站的呃积分，这个他他是给我用了 workbaby 的自定义模型，但是不知道为什么就是我 workbaby 的这个账号，就是他可以用他的模型，然后可以用账号内置模型，但是用不了自定义模型。"

**校正**
拆开是两个不同的东西：
1. 买的中转站积分 → 兑换成了 **WorkBuddy 的自定义模型**额度；
2. 但 WorkBuddy 账号里：**内置模型能用，自定义模型用不了**。
这是**一个具体的故障**，不是知识缺口。他后面自己说了"这不是一个工单啊，这是很多个问题"——所以它要**独立成票**，不能塞进 #51。

**实际需求**
定位"内置模型通、自定义模型不通"的断点在哪一层（账号权限 / 中转站协议 / DSH 插件映射），并给出可复现的判断步骤。

**归属**
票 #52，**被 #51 阻塞**：先把接入链路判清楚，才知道自定义模型这一段断在链路哪一环。这是全图唯一一条阻塞边。

**待确认**
- [ ] 这条是"先修好"还是"先搞清楚原理"？（推荐先修：它每天都在耗他用不了的那部分额度）

## 6. 视频：去水印 + 加看不见的水印

**原话**
> "就是我要下载一些视频，然后要把他的水印去掉，呃，这个要去 GitHub 去找一些好的方案，然后我去研究对比学习。然后呢，还有一个就是呃，我要去添加一些水印，而且这个水印在视频上看不出来，这个也要去学习，这相当于2大块嘛。"

**校正**
- "这个水印在视频上看不出来" → 两种可能：**盲水印 / 隐写**（人眼不可见、算法可检出），或**肉眼不易察觉但存在的可见水印**（低对比度、角落小字）。**这是本轮最需要他拍板的一个词**，两种方案的技术栈完全不同。
- "去 GitHub 去找一些好的方案，然后我去研究对比学习" → 他要的是**横评**，不是让我直接选一个装上。

**实际需求**
两条独立的线：①去水印的候选方案横评（效果 / 可维护性）；②加水印的方案选型（先定"看不见"是哪一种）。

**归属**
票 #53（去水印）、票 #54（不可见水印），互不阻塞。

**待确认**
- [ ] "看不见的水印" = 盲水印（机器可检、人眼不可见），还是 = 低对比度可见水印？
- [ ] 去水印这条线的用途是"自己看"还是"要再分发"？
